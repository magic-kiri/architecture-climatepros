4 · Azure Cache for Redis — Infrastructure Layer New
STREAM · dispatch:stream

Tracks incoming dispatch requests per division. Durable buffer between .NET Legacy API and the Container Apps workers.

MUTEX · lock:div:*

Distributed per-division lock. Guarantees sequential, non-parallel processing — no two workers touch the same division at once.

LIST · resp:{dispatchId}:{techId}

Per-technician reply channel. Azure VM API LPUSHes the Accept/Reject; the worker BLPOPs it — instant wake, no polling. EXPIRE 60s self-cleans.

Fault Tolerance — PEL Expiration & Dual-Execution Shield New

If Task C2 crashes or processing exceeds the visibility timeout, its message stays unacknowledged in the Pending Entries List (PEL):

  1. Surviving worker (e.g. C1) claims the stuck message via XCLAIM
  2. C1 must first acquire lock:div:Div_A before running the flow
  3. Guardrail: if C2 was merely slow (not dead), the live lock blocks C1 → prevents dual execution. If C2 truly died, the lock expires and C1 safely takes over.

Net effect: exactly-once dispatch to technicians — no duplicate assignments, even under crashes or stalls.
