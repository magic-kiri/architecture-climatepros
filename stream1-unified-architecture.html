1. Stream 1 Overview

ClimatePros runs commercial refrigeration & HVAC field service: ~900–1,000 technicians, 46 branches, 10,000+ sites. Work orders arrive automatically. Everything after that still runs on a phone call and a technician's memory. Three use cases, three bottlenecks, one job.

Where AI sits: Use Case A is a deterministic algorithm — no LLM. It replaces a decision a dispatcher already makes by hand, so it must be explainable and repeatable. Use Cases B and C use AI, and in both the technician can always override it.

A Algorithm · no LLM

Auto-Dispatch — finding the right technician

Web portal · Dispatcher

Confirming a tech today means dialling ~40 candidates one at a time, ~2–3 min each — the throughput ceiling for two dispatchers per branch.

We solve: rank techs on distance, familiarity, time-to-free and job priority; push an accept/decline offer and cascade automatically. Pure rules and math — no LLM — so every assignment is explainable.

B AI · tech overrides

Job Summarisation Copilot — changing the job status

Mobile · Technician at end of job

Every job's mandatory closeout means 10–15 min of forms and two free-text notes — done properly. In practice ~40% of notes end up ≤40 characters.

We solve: restructure the tech's rough words into a clean note for customer and office, and suggest form values from similar past jobs. Never fabricates, never blocks Save. Target: 10–15 min → ~15 s.

C AI · tech overrides

Technician Parts Finder — finding the part that isn't on the truck

Mobile · Technician on-site

When the first three sources (truck, nearby techs, warehouse) come up empty, the fourth is a phone call to a supplier who may not answer — billable hours burned, or a second truck roll.

We solve: AI suggests the likely part from the problem and equipment; one search shows where it is across all four sources. The tech decides where to pick it up — no price ranking, no ordering.

Work order in → (A) the right tech is offered the job on the web portal → tech arrives on site → (C) the missing part is found on mobile without a phone call → (B) the closeout note writes itself. Full step-by-step diagrams for all three: see §5 Operational Flows.

Cloud placement: the existing FieldJetX platform and all new infra run on Azure; the SQL Server system of record stays on AWS (sole cross-cloud dependency). This restates the existing-platform cloud from the per-use-case docs, which describe the existing platform as running on AWS EC2.
